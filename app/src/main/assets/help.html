How a TOTP code is made

TOTP means Time-based One-Time Password. The 6-digit code on your Dashboard is not sent to you by anyone. Your phone works it out, and the server (here: this app) works out the same number independently. If the two numbers match, you must know the secret.

The recipe

Secret20 random bytes, shown as the QR code when you set up
Clockseconds since 1 Jan 1970
↓
1. Time stepclock ÷ 30 = a counter that changes every 30 seconds
↓
2. HMACthe counter is mixed with the secret using HMAC-SHA1 (a keyed fingerprint)
↓
3. Dynamic truncationthe last 4 bits pick 4 bytes of the fingerprint to keep
↓
4. Last 6 digitsthe number is cut down with “remainder after dividing by 1,000,000”
↓
287 082

Why it is safe to use offline

Nothing in the recipe needs a network. It needs only the secret and the clock. That is why the code keeps working in airplane mode.

Why the code changes every 30 seconds

The counter in step 1 goes up by one every 30 seconds, so the whole result changes. A stolen code is useless half a minute later. The ring on the Dashboard shows how long is left.

Why your code may be accepted slightly early or late

Phone clocks are never perfectly equal. When checking a code, the app also accepts the step just before and the step just after the current one (±1 step, about 30 seconds either way). A code two steps away is rejected.

A worked example from the standard

WhatValue
Secret (ASCII)12345678901234567890
Time59 seconds after 1 Jan 1970
Time step (59 ÷ 30)1
8-digit code94287082

This is one of the test values in RFC 6238 (Appendix B). This app’s unit tests check that its hand-written engine produces exactly these numbers.

What to do if your code is rejected

  • Check that the date and time on your phone are set to automatic.
  • Make sure you are reading the code for this app and not another account.
  • If you changed the code length, period or algorithm in Settings, set up your authenticator again so both sides agree.
  • Lost the authenticator? Use one of your backup codes.
